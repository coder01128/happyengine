# Brief 02: Contracts synthetic test set

**Repo:** `happyengine` · **Branch:** `contracts/test-set` · **Requires:** brief 01 merged

Read `CLAUDE.md` and `docs/contracts-plan.md` first.

## Goal

Build the test set **before** the pipeline. Real contracts come later. Until then, the five sample agreements in `happyai/demo-contracts.html` become real PDFs, with:

- the correct recorded values
- the correct review flags
- the correct key dates
- the correct highlight box for every value

The eval (brief 05) scores the pipeline against these files.

## Out of scope

- No pipeline code, no database changes, no app changes.
- Don't edit anything in the `happyai` repo. Read it only.

## Step 1: render the digital PDFs

Write `eval/contracts/render/render-demo.ts` with Playwright. Add `playwright` as a root dev dependency and install Chromium with `npx playwright install chromium`.

1. **Load the demo.** Open `../happyai/demo-contracts.html` from `file://`. Read `FIXTURE` with `page.evaluate(() => FIXTURE)`. It's a top-level `const`, so it's reachable from evaluated code.
2. **Build one print document per file.**
   - Each fixture page goes on its own A4 page, using the demo's own CSS (copy its `<style>` block) and the `.paper` / `.legal` classes.
   - Remove the demo's SAMPLE strip if it overlaps clause text. Keep "(sample)" in the counterparty names.
   - **C1 is two files.** The lease pages go in `c1-lease.pdf`. The final "Addendum 1" page goes in `c1-addendum.pdf`, because in real life an addendum arrives as its own document.
3. **Blank lines.** The demo draws C5's blank term with a CSS underline. That leaves no text in a PDF, and no real contract works that way. In the print copy, put literal underscores (`__________`) inside `.blank`, so the text layer holds "for a period of __________ months".
4. **Print.** Use `page.pdf({ format: 'A4', printBackground: true })`.
5. **Record the boxes.** Before printing, record for every `[data-field]` element its page number (1-based, within its file) and its `getBoundingClientRect()` relative to its page. Convert CSS px to PDF points (× 0.75, top-left origin) and write them to `boxes.json`:
   ```json
   { "c1-lease.pdf": { "c1-4-1": [{ "page": 2, "x": 71.2, "y": 402.0, "w": 452.5, "h": 28.1 }] } }
   ```
6. **Deterministic output.** Running the script twice gives identical `boxes.json`. PDFs may differ only in metadata dates; set a fixed creation date if Playwright allows.

## Step 2: render the scan-style PDFs

For `scan-marula/`:

1. Screenshot each rendered page at 150 dpi as JPEG, quality 70.
2. Apply a light grey tint, slight blur (0.4px) and faint noise with a CSS filter or a canvas pass.
3. Put the images into an HTML page, one image per A4 page, and print to PDF. The result has **no text layer**. Check this: PDF.js `getTextContent()` returns no items.
4. **No rotation yet.** Boxes stay valid, so `boxes.json` is the same as the digital set, recomputed from the image positions to prove it.

The local PDF.js parser can't read these files. Only LlamaParse (or another OCR parser) can. This set exists to test that.
