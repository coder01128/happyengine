| --- | --- | --- |

## Files in a sample folder

- `sample.json`: as-at date, organisation name, and each agreement's files in order (C1 is the lease plus its addendum). `"synthetic": true` marks made-up documents that may be sent to LlamaParse and Claude; real client samples never have it. `"scanned": true` says the files are scans, so they are read at the preset's scanned tier (the pipeline does the same for an agreement ticked "Scanned copy").
- `*.pdf`: the agreements.
- `expected.json`: the correct answers, written by hand. `render-demo.ts` copies it (and `sample.json`) from `demo-marula/` to `scan-marula/`.
- `boxes.json`: the correct highlight box for every `data-field` in the demo, generated by `render-demo.ts`. Each box covers the element's text, not its whole block, so a short clause in a full-width block gets a box around its words.
- `parsed/<parser>-<tier>/<file>.json`: a recorded `ParsedDocument`, written by `node scripts/parse-file.ts <pdf> --parser pdfjs|llamaparse [--tier agentic]`. The fixture parser replays these.

### `boxes.json`

```json
{ "c1-lease.pdf": { "c1-4-1": [{ "page": 2, "x": 27.9, "y": 491.5, "w": 539.5, "h": 16.9 }] } }
```

PDF points (1/72 inch), origin at the top-left of the page, `page` is 1-based within that file. A field can have more than one box.

### `expected.json`

```
{ asAt, alertWindows: { attention, upcoming }, agreements: { <id>: { fields, flags, dates } } }
```

**`fields`**: one entry per field key (`counterparty`, `startDate`, `endDate`, `termMonths`, `renewal`, `notice`, `fee`, `feeChange`, `deposit`). Only the fields listed are scored for that agreement.

```json
{ "value": <typed value>, "source": ["<data-field id>"], "also": ["<data-field id>"] }
```

- `source`: the extracted source must overlap one of these boxes. `also`: other places the same value is stated; overlapping one of these also counts.
- `values` instead of `value`: the agreement states the field more than once, differently (C3 notice). Each item is `{ value, source }` and every one must be found.
- `supersedes`: an earlier value that an addendum replaced (C1 notice). Also `{ value, source }`.
- `derived`: the value is calculated, not stated (C2 end date).

Typed values, so the eval compares meaning, not wording:

| Kind | Shape |
| --- | --- |
| Date | ISO string, `"2027-01-31"` |
| Money | integer cents, `6400000` |
| Fee | `{ "cents": 485000, "per": "month", "vat": "excluded" }`, or `{ "text": "Rates per Schedule A" }` when no amount is stated |
| Duration (notice) | `{ "amount": 3, "unit": "days" \| "months", "before": "expiry" \| "renewal" \| "end_of_initial_period" }`. "Calendar months" and "months" are both `months`. `before` is left out where the brief leaves it out |
| Renewal | `{ "kind": "option" \| "automatic", "periodMonths": 36 }` or `{ "kind": "month_to_month" }` |
| Fee change | `{ "kind": "schedule", "steps": [cents, ...] }`, `{ "kind": "percent_escalation", "percent": 10, "every": "anniversary" }` or `{ "kind": "unquantified" }` |
| Missing | `"not_stated"` (the agreement doesn't say), `"blank"` (a blank line left empty in the signed copy). Both still have a `source`: the nearest clause |

**`flags`**: the review items the rules must raise. `{ "kind": "conflict" | "unclear" | "blank", "field": "<field key>", "about": "..." }`. An empty list means no flags; any flag raised there is wrong.

**`dates`**: key dates as at `asAt`, with alert windows of 30 days (needs attention) and 90 days (upcoming).

```json
{ "key": "renewal_notice", "label": "Renewal notice deadline", "value": "2026-10-31", "derivation": "2027-01-31 − 3 months", "status": "needs_attention" }
```

`status` is `passed`, `needs_attention`, `upcoming` or `later`. A date that can't be worked out until a flag is reviewed has `"value": "pending_review"` and `"status": null` (C3). An empty list means no key dates (C5).

## Running the eval

The free check (no network, digital samples only; must stay at 100%):

```
npm run eval:contracts -- --parser pdfjs --extractor fixture:extract-perfect
```

The full live check (all samples, saved parses reused, Claude three times):

```
npm run eval:contracts -- --parser llamaparse --extractor claude --repeat 3
```

Prints, per sample: fields correct, grounding (quotes found, exact or fuzzy), highlights (sources whose box overlaps the expected box with IoU ≥ 0.5, or lies inside it), flags found and unexpected, key dates correct. Then a summary: **per-field accuracy**, the **grounding match rate**, the **highlight-on-expected-quote rate**, the spread across runs, and **every failure with its reason**. Exit code 1 on any wrong field, missed or unexpected flag, or wrong date in any run.

- `--parser fixture|pdfjs|llamaparse`: `fixture` (the default) replays a saved parse from `parsed/`. The others parse and save under `parsed/<parser>-<tier>/`, and reuse that next time unless `--reparse` is given, so LlamaParse costs credits only once.
- `--extractor fixture:<name>|claude`: `fixture:extract-perfect` (the default) replays `recorded/extract-perfect.json`, the answer a perfect extractor gives. `claude` calls the API (needs `ANTHROPIC_API_KEY` and `ANTHROPIC_MODEL` in `supabase/functions/.env`); add `--record` to save its output as `recorded/extract-<model>.json` for free replays, and `--repeat N` to see which fields change between runs.
- Live adapters (LlamaParse, Claude) only run on samples with `"synthetic": true`. Anything else is refused: real documents need the POPIA gates first (`--allow-offshore` once they're signed off).
- `scan-marula` is skipped unless `--parser llamaparse` is used: its pages are images only.

`recorded/` holds extraction outputs: `extract-perfect.json` is hand-built from `expected.json` and the demo text; `extract-<model>.json` files are recordings of real runs.

`expected.json` lists C3's "End of initial period" (30 Sep 2026, passed): the brief 05 rules derive C3's end date from start + 6 months − 1 day. The demo's date panel left it out.
